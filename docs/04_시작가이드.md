# 봉사모아 시작 가이드
### 클로드 AI 처음 쓰는 사람이 웹서비스를 만들어 배포하기까지

작성일: 2026년 8월 8일
대상: 코딩 경험 없음 / 클로드 처음 / 웹 배포 처음

---

## 0. 먼저, 큰 그림

당신이 앞으로 하게 될 일을 한 문장으로 요약하면 이렇습니다.

> **내 컴퓨터에서 웹사이트 파일을 만들고 → 인터넷의 어떤 서버에 올려두면 → 누구나 주소를 쳐서 들어올 수 있다.**

이게 전부입니다. 나머지는 이 세 단계를 "어떤 도구로" 하느냐의 문제일 뿐입니다.

그리고 좋은 소식: **당신이 코드를 직접 타이핑할 필요는 없습니다.** 클로드가 씁니다. 대신 당신은 이 두 가지를 할 수 있어야 합니다.

1. **뭘 만들지 정확히 설명하기** (이게 실제 난이도의 70%)
2. **결과물을 보고 뭐가 잘못됐는지 말해주기**

즉, 당신의 역할은 "개발자"가 아니라 **"기획자 겸 사장"** 입니다. 클로드가 개발팀이고요. 이 문서는 사장이 알아야 할 최소한의 지식을 다룹니다.

# PART 1. 클로드 기본 셋팅

## 1-1. 클로드를 쓰는 3가지 방식

같은 클로드지만, 껍데기가 3종류입니다. 이걸 헷갈리면 시작부터 꼬입니다.

| 방식 | 이게 뭐냐면 | 봉사모아에 쓸까? |
|---|---|---|
| **클로드 웹/앱 채팅** | claude.ai 에서 그냥 대화하는 것 | 기획·아이디어 정리용 ⭕ |
| **Cowork (지금 이 화면)** | 클로드 데스크톱 앱 안에서, 클로드가 **내 컴퓨터 폴더에 직접 파일을 만들어주는** 모드 | 초반 제작에 ⭕⭕ |
| **Claude Code** | 검은 터미널 창에서 쓰는 개발자 전용 도구. 프로젝트 전체를 훨씬 강력하게 다룸 | 프로젝트가 커지면 ⭕⭕⭕ |

### 결론: 당신의 경로

```
[1단계] Cowork 로 시작        ← 지금 여기. 설치할 것 거의 없음
   ↓  코드 파일이 20개쯤 넘어가고 답답해지면
[2단계] Claude Code 로 이사   ← 그때 가서 배워도 늦지 않음
```

**지금 Claude Code를 억지로 배우지 마세요.** 터미널, 명령어, Git… 한꺼번에 배우면 시작도 못 하고 지칩니다. Cowork로 눈에 보이는 결과물을 먼저 만드는 게 훨씬 중요합니다.

> 참고: Claude Code는 나중에 필요해지면 `npm install -g @anthropic-ai/claude-code` 한 줄이면 설치됩니다 (Node.js 18 이상 필요). 지금은 이런 게 있다는 것만 알아두세요.

## 1-3. Cowork 셋팅 — 딱 3가지만

### ① 작업 폴더 연결 (가장 중요, 필수)

지금 상태에서 제가 만든 파일은 임시 폴더에 저장돼서 세션이 끝나면 사라질 수 있습니다.
내 컴퓨터에 **봉사모아 전용 폴더**를 만들고 클로드에게 연결해주세요.

```
예: C:\Users\rnjsg\Documents\bongsamoa
```

폴더를 만든 뒤, 저에게 **"이 폴더 연결해줘"** 라고 말하면 폴더 선택 창이 뜹니다.
연결하면 그때부터 제가 만드는 모든 파일이 **당신 컴퓨터에 진짜로 저장**됩니다.

### ② 프로젝트(지식) 활용

지금 이 대화는 `봉사모아_웹/앱 만들기` 프로젝트에 속해 있습니다. 여기에 기획서·화면 스케치·참고자료를 올려두면 **매번 설명을 반복하지 않아도** 제가 참고합니다.

올려두면 좋은 것:
- 봉사모아 기획서 (한 장짜리라도)
- 참고하고 싶은 다른 사이트 화면 캡처
- 화면 구성 손그림 사진

### ③ 커넥터(연동)는 나중에

Slack, Notion 같은 외부 서비스 연동 기능이 있지만 **지금은 신경 쓰지 마세요.** 웹사이트 만드는 데 필요 없습니다.

## 1-4. 클로드에게 말 거는 법 (실전에서 제일 중요)

초보자가 가장 많이 실패하는 지점입니다. 나쁜 예와 좋은 예를 비교해보세요.

**❌ 나쁜 요청**
> 봉사 사이트 만들어줘

→ 결과: 그럴듯하지만 당신이 원한 게 아닌 무언가가 나옴

**✅ 좋은 요청**
> 봉사활동 목록 페이지를 만들어줘.
> - 카드 형태로 한 줄에 3개씩
> - 각 카드에 들어갈 정보: 봉사명, 기관명, 지역, 모집기간, 남은 인원
> - 상단에 지역 선택 드롭다운과 검색창
> - 모바일에서는 한 줄에 1개씩 보이게
> - 색은 초록색 계열, 따뜻한 느낌

### 3가지 원칙

1. **한 번에 하나씩.** "로그인, 목록, 지도, 알림 다 만들어줘" ❌ → 한 화면씩 완성
2. **완성본이 아니라 '방향'을 먼저 물어라.** "이런 서비스 만들 건데, 화면 구성 3가지 안 제안해줘"
3. **모르면 모른다고 말해라.** "Supabase가 뭔지 모르겠어, 초등학생한테 설명하듯 알려줘" — 이게 부끄러운 게 아니라 가장 효율적입니다.

### 막혔을 때 쓰는 마법의 문장

- "지금 상황을 정리해주고, 다음에 뭘 해야 하는지 하나만 알려줘"
- "이거 왜 안 되는지 원인을 3가지 추측해보고, 확인하는 방법을 알려줘"
- "방금 만든 코드가 뭘 하는 건지 비유로 설명해줘"

# PART 2. 웹서비스 배경지식

## 2-1. 웹사이트는 어떻게 작동하는가

식당에 비유하면 정확합니다.

```
   손님              웨이터/홀              주방              창고
 [ 브라우저 ]  ←→  [ 프론트엔드 ]  ←→  [ 백엔드 ]  ←→  [ 데이터베이스 ]
  크롬, 사파리       보이는 화면          처리 로직         정보 저장소
```

- **브라우저**: 사용자가 보는 창 (크롬, 사파리)
- **프론트엔드 (Frontend)**: 눈에 **보이는** 부분. 버튼, 글자, 색깔, 배치
- **백엔드 (Backend)**: 눈에 **안 보이는** 부분. "이 사람이 진짜 회원 맞나?", "신청 인원 +1" 같은 처리
- **데이터베이스 (DB)**: 정보를 쌓아두는 곳. 회원 목록, 봉사활동 목록, 신청 내역

봉사모아로 옮기면:
- 사용자가 "신청하기" 버튼을 누른다 → **프론트엔드**
- 마감됐는지 확인하고 신청을 처리한다 → **백엔드**
- 누가 뭘 신청했는지 기록된다 → **데이터베이스**

## 2-2. 반드시 알아야 할 용어 12개

이것만 알면 저와 대화가 통합니다.

| 용어 | 한 줄 설명 | 비유 |
|---|---|---|
| **HTML** | 화면의 뼈대 (제목, 문단, 버튼) | 건물 골조 |
| **CSS** | 화면의 꾸밈 (색, 크기, 배치) | 페인트·인테리어 |
| **JavaScript** | 화면의 동작 (클릭하면 뭐가 일어남) | 전기·수도 배선 |
| **React** | JavaScript를 편하게 쓰게 해주는 도구 | 전동 드릴 (망치 대신) |
| **Next.js** | React로 웹사이트를 통째로 만들게 해주는 틀 | 조립식 주택 키트 |
| **API** | 프로그램끼리 정보를 주고받는 창구 | 은행 창구 |
| **데이터베이스** | 정보 저장소 | 창고 |
| **서버** | 24시간 켜져 있는 남의 컴퓨터 | 임대 매장 |
| **배포(Deploy)** | 내 코드를 서버에 올려 세상에 공개 | 개업 |
| **도메인** | 인터넷 주소 (`bongsamoa.com`) | 가게 주소·간판 |
| **Git / GitHub** | 코드 버전 저장 + 백업 | 무한 되돌리기 + 금고 |
| **반응형(Responsive)** | 화면 크기에 맞춰 배치가 바뀜 | 접이식 가구 |

## 2-3. "모바일 앱" 오해 풀기

많은 사람이 헷갈리는 부분입니다. 모바일에서 쓰는 방법은 3가지입니다.

| 종류 | 설명 | 난이도 | 심사 | 비용 |
|---|---|---|---|---|
| **반응형 웹** | 폰 브라우저로 접속. 앱처럼 잘 보이게 만듦 | ★☆☆ | 없음 | 무료 |
| **PWA** | 반응형 웹 + "홈 화면에 추가" 가능. 아이콘 생기고 앱처럼 열림 | ★★☆ | 없음 | 무료 |
| **네이티브 앱** | 앱스토어·플레이스토어에 올리는 진짜 앱 | ★★★ | 있음 (수일~수주) | 애플 연 $99 + 구글 $25 |

**당신의 경로: 반응형 웹 → PWA → 필요하면 네이티브 앱**

핵심은 **처음부터 반응형으로 잘 만들어두면**, 나중에 앱으로 갈 때 화면 코드를 상당 부분 재활용할 수 있다는 겁니다. 그래서 아래 기술 조합을 추천합니다.

# PART 3. 봉사모아에 쓸 기술 조합

초보자가 웹으로 시작해서 앱까지 갈 수 있는, 가장 무난한 조합입니다.

```
프론트+백엔드 :  Next.js          (화면 + 서버 로직을 한 프로젝트에서)
데이터베이스  :  Supabase         (DB + 로그인 기능을 통째로 제공)
배포         :  Vercel           (GitHub에 올리면 자동 배포)
코드 저장    :  GitHub           (백업 + 배포 연결)
디자인       :  Tailwind CSS     (클로드가 가장 잘 다루는 스타일 도구)
```

### 왜 이 조합인가

- **전부 무료로 시작** 가능합니다
- **서버 관리를 안 해도 됩니다** (초보자에게 이게 결정적입니다)
- 클로드가 이 조합에 대한 학습량이 가장 많아 **에러가 적습니다**
- 나중에 앱으로 갈 때 Supabase는 그대로 씁니다 → **마이그레이션 부담이 작음**

### 무료 한도 (2026년 기준, 정확한 값은 각 사이트에서 확인)

**Vercel (Hobby, 무료)**
- 월 데이터 전송 100GB, 빌드 6,000분
- ⚠️ **비상업적 용도 한정**. 광고·유료화 등 수익이 발생하면 Pro($20/월)로 전환 필요
- 한도 초과 시 요금이 청구되는 게 아니라 **서비스가 일시 정지**됨 (초보자에겐 오히려 안전)

**Supabase (Free)**
- DB 500MB, 파일 저장 1GB, 월 활성 사용자 50,000명
- ⚠️ **7일간 아무 접속이 없으면 프로젝트가 일시 정지**됨 (대시보드에서 다시 켜면 됨)
- ⚠️ **자동 백업 없음.** 실제 사용자 데이터가 쌓이기 시작하면 유료 전환($25/월)을 고려

**도메인**: `.com` 기준 연 1~2만원. 없어도 `프로젝트명.vercel.app` 주소로 무료 운영 가능합니다.

### 봉사 데이터는 어디서?

봉사모아의 핵심은 결국 **데이터**입니다. **공공데이터포털(data.go.kr)** 에 관련 오픈API가 이미 공개돼 있습니다.

- 행정안전부 **봉사참여정보서비스** — 지역별·분야별·기간별 봉사 참여정보 조회
- 행정안전부 **자원봉사 프로그램 및 캠페인** — 봉사명, 기관, 모집기간, 인원, 위경도 등
- 1365 연계 관련 API 다수

회원가입 후 **활용신청**을 하면 인증키를 받아 쓸 수 있습니다. 신청 승인에 며칠 걸릴 수 있으니 **가장 먼저 신청해두는 걸 권합니다.**

> ⚠️ 주의: 공공 API는 문서가 불친절하고 실제 응답이 문서와 다른 경우가 흔합니다. 이건 당신 잘못이 아닙니다. 실제 응답 데이터를 저에게 그대로 붙여넣어 주시면 거기 맞춰 코드를 짜겠습니다.

# PART 5. 초보자가 반드시 겪는 일들 (미리 알아두기)

정상입니다. 개발의 절반이 에러 고치기입니다. **에러 메시지를 통째로 복사해서 저에게 붙여넣으세요.** 요약하지 마세요. 원문 그대로가 가장 도움이 됩니다.

### 😵 "잘 되던 게 갑자기 안 돼요"
그래서 **Git/GitHub**를 씁니다. 되돌릴 수 있습니다. 중요한 게 완성될 때마다 저장(커밋)하는 습관을 들이세요.

### 🤯 "코드가 뭔 소린지 하나도 모르겠어요"
