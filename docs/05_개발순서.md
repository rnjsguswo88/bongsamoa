## 1단계 · 빈 페이지를 인터넷에 올리기 (반나절)

**기능 0개.** 「봉사모아」 한 줄만 있는 페이지를 진짜 주소로 띄웁니다.

### 왜 이걸 먼저 하나

초보자에게 가장 큰 심리적 장벽은 코딩이 아니라 **«배포»라는 미지의 단계**입니다. 기능을 다 만든 뒤에 배포를 처음 시도하면, 그때 문제가 생기면 원인이 100군데입니다.

**지금 하면 원인이 한 군데**입니다. 그리고 주소창에 내 사이트가 뜨는 걸 한 번 보고 나면 남은 과정이 전부 «채우기»가 됩니다.

### 순서

```
1. Next.js 프로젝트 만들기
2. GitHub에 올리기
3. Vercel에 GitHub 연결 → 자동 배포
4. 주소 확인 (bongsamoa.vercel.app 같은 것)
```

### 저에게 이렇게 말하세요

> Next.js 프로젝트를 만들고 GitHub에 올린 다음 Vercel에 연결해줘.
> 나는 처음이니까 한 단계씩, 내가 뭘 눌러야 하는지 알려줘.

### 완료 기준

**휴대폰으로 그 주소를 열어서 보입니다.** 컴퓨터 말고 휴대폰으로 확인하세요.

### 함정

- **도메인은 아직 사지 마세요.** `vercel.app` 주소로 충분합니다. 서비스가 돌아가면 그때
- 이후로 **GitHub에 올리면 자동으로 배포**됩니다. 이게 Vercel을 쓰는 이유입니다

## 5단계 · 봉사자 화면 (1~2주)

> 📌 **신청 인원(동반자) 설계가 여기 들어갑니다.** `docs/00_현재상태.md`의 "4단계 설계 완료 › 1. 신청 인원" 절 참고.
> 신청 팝업이 2단계(인원 → 인원에 맞는 폼)로 바뀌므로, 3번을 만들 때 함께 봅니다.

### 만드는 순서

```
1. 봉사 찾기 (목록 · 필터)
2. 센터 상세 (달력 · 센터 정보)
3. 신청 2단계(인원 → 폼) → 신청 완료   ← 동반 인원 · 2명 이상 연락처가 여기
4. 내 봉사 (다가오는 · 지난) · 인원 변경
5. 봉사 취소 · 참석 확인
6. 후기 쓰기 · 목록
```

### 완료 기준

**다른 사람 계정으로 신청하고, 센터 계정 명단에 그 사람이 뜨고, 취소하면 사라집니다.**

브라우저 두 개(하나는 시크릿 창)를 띄워놓고 확인하세요.

### 함정

- **신청은 반드시 DB 함수로.** 정원 검사 → 시간 겹침 검사 → 생성이 한 덩어리여야 합니다
- 목록 쿼리에서 **센터 연락처를 빼지 마세요** — 센터 정보에서는 공개하기로 했습니다. 대신 **목록 카드에는 넣지 마세요**
- 취소한 회차에 다시 신청하면 `unique` 제약에 걸립니다. **새로 넣지 말고 되살리세요**(UPSERT)

```
3. 모임원들에게 링크 보내고 신청받기
4. 실제로 봉사 나가기
5. 안 되는 것 적어두기
```

### 완료 기준

이게 성공 기준 그 자체입니다.

> **다음 달 봉사 일정을 엑셀이 아니라 봉사모아로 운영했다.**

### 여기서 반드시 나올 문제들

- «전화로 신청한 분» — 직접 추가 기능이 실제로 편한가
- «비 와서 취소» — 알릴 방법이 없다는 게 얼마나 불편한가
- «참석 확인을 아무도 안 누른다» — 이게 실제로 일어나는지
- 모임원들이 가입 단계에서 어디서 멈추는지

**이 목록이 다음에 만들 것을 정해줍니다.** 지금 상상으로 정하지 마세요.

### 함정

- **모임원에게 «테스트해줘» 라고 하지 마세요.** 그냥 «이제 여기로 신청해주세요» 라고 하세요. 테스트라고 하면 진짜처럼 안 씁니다
- 문제가 나와도 **그 자리에서 고치지 마세요.** 적어두고 봉사가 끝난 뒤에 고칩니다

## 8단계 · PWA, 그다음 앱 (나중)

### 먼저 PWA

`manifest.json` 파일 하나와 서비스워커를 추가하면 **홈 화면에 아이콘이 생기고 전체 화면으로 뜹니다.** 1~2일이면 됩니다.

### 앱으로 넘어갈 시점

`03_웹에서_앱으로.md` 3장의 숫자로 판단합니다. 감으로 정하지 마세요.

- 센터 10곳 이상이 매달 일정을 올린다
- 월 활성 봉사자 300명 이상
- «알림이 없어서 까먹었다» 는 말이 반복된다

**셋 중 하나도 해당 안 되면 웹을 더 고칠 때입니다.**

### 앱보다 먼저 검토할 것

**카카오 알림톡.** 웹만으로 되고 건당 10원 안팎입니다. «봉사 하루 전 알림» 하나만으로 노쇼가 크게 줄어드는데, 이걸 위해 앱을 만들 필요가 없습니다.

## 막혔을 때

### 에러가 뜨면

**통째로 복사해서 붙여넣으세요.** 요약하거나 «에러 났어» 라고만 하면 원인을 못 찾습니다.

### 잘 되던 게 갑자기 안 되면

**직전에 뭘 바꿨는지** 말해주세요. 그게 원인의 90%입니다. Git을 쓰고 있다면 되돌릴 수 있습니다.

### 코드가 무슨 소린지 모르겠으면

**괜찮습니다.** 다만 이 셋은 알아야 합니다.

- 이 파일이 **어느 화면**인지
- 데이터가 **어디서 와서 어디로 가는지**
- **뭘 고치면 뭐가 바뀌는지**

문법은 몰라도 됩니다. 구조만 아세요.

### 하루 이상 막히면

방법을 바꿀 때입니다. **그 기능을 빼고 다음으로 넘어가세요.** 나중에 돌아오면 대개 쉽게 풀립니다.
