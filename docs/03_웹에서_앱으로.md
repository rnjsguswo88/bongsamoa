# 웹 먼저, 앱은 나중에

버전 1.0 · 2026-08-08

> **전제** — 봉사모아는 **웹으로 먼저 운영**하고, 자리를 잡으면 앱으로 넘어갑니다.
> 이 문서는 "지금 웹에서 대충 해두면 나중에 앱에서 크게 고생하는 것"들만 모았습니다.

---

## 0. 왜 웹부터인가

| | 웹 | 앱 |
|---|---|---|
| 첫 배포까지 | 며칠 | 심사 포함 2~4주 |
| 고치고 다시 올리기 | 몇 분 | 심사 다시 (수일) |
| 비용 | 사실상 0 | 애플 연 $99 + 구글 $25 |
| 링크 공유 | 그냥 됨 | 앱 설치 유도부터 필요 |

초기에는 **하루에도 몇 번씩 고칩니다.** 심사가 낀 앱으로는 그 속도가 안 나옵니다.

---

## 1. 지금 안 해두면 나중에 고생하는 것 5가지

### ① URL 구조 ⭐ 가장 중요

앱으로 넘어갈 때 **"웹에서 공유했던 링크가 앱에서도 열리게"** 만들 수 있습니다. 단, **URL이 처음부터 잘 잡혀 있어야** 가능합니다.

| 화면 | URL | 앱에서 |
|---|---|---|
| 센터 | `/c/{센터코드}` | 앱의 센터 화면 |
| 특정 회차 | `/c/{센터코드}?d=2026-08-15` | 그 날짜가 열린 상태 |
| 후기 | `/r/{후기ID}` | 후기 상세 |
| 봉사 찾기 | `/find?region=seoul&day=sat` | 필터가 적용된 목록 |

**하면 안 되는 것**

- `/page?id=12345` 처럼 **숫자 그대로 노출** → 센터가 몇 개인지 다 드러나고, 주소가 안 예쁩니다. `happy-dog` 같은 **글자 코드**를 씁니다
- 화면 이동을 URL 없이 처리 → 공유도 뒤로가기도 안 됩니다
- 나중에 URL 구조 변경 → **이미 공유된 링크가 전부 깨집니다.** 한 번 정하면 못 바꾼다고 생각하세요

> 카카오톡으로 공유한 링크는 몇 달 뒤에도 누군가 누릅니다. 그때 404가 뜨면 그 사람은 다시 안 옵니다.

### ② 소셜 로그인 리다이렉트

카카오 로그인은 **"로그인 끝나면 어디로 돌려보낼지"** 주소를 미리 등록해둬야 합니다.

| | 웹 | 앱 |
|---|---|---|
| 돌아올 주소 | `https://bongsamoa.kr/auth/callback` | `bongsamoa://auth/callback` |

- 카카오 개발자 콘솔에 **두 개 다 미리 등록**해두세요. 나중에 추가해도 되지만 잊기 쉽습니다
- 앱 전용 주소(`bongsamoa://`)를 정해두고 문서에 적어둡니다

### ③ 화면 크기 — 이미 되어 있음

시안이 **모바일 폭 고정 + 화면 높이 채움**으로 되어 있어서, 그대로 앱에 넣어도 어색하지 않습니다.

- `100dvh` 사용 — 모바일 브라우저 주소창이 사라져도 안 깨집니다
- `safe-area-inset` 적용 — 아이폰 하단 인디케이터, 안드로이드 내비바에 안 가립니다

### ④ 아이콘·폰트를 외부에서 불러오지 않기

앱 안에서는 인터넷이 느리거나 끊길 수 있습니다. 외부에서 아이콘을 불러오면 **네모 박스만 뜹니다.**

- 시안은 아이콘을 **파일 안에 직접** 넣어뒀습니다 (외부 요청 0건)
- 폰트만 외부에서 받는데, 앱으로 갈 땐 **파일로 포함**시킵니다

### ⑤ 알림 — 앱의 진짜 이유

**앱을 만드는 이유의 대부분은 푸시 알림입니다.** 웹에서는 알림을 보내기 어렵습니다.

| 시점 | 알림 내용 | 효과 |
|---|---|---|
| 봉사 하루 전 | "내일 10시 행복 유기견 보호소" | **노쇼가 크게 줄어듭니다** |
| 봉사 끝난 날 저녁 | "참석 완료 눌러주세요" | 참석 확인율이 올라갑니다 |
| 찜한 센터 새 일정 | "9월 일정이 열렸어요" | 재방문 |

- **알림 문구와 시점은 지금 정해둡니다.** 앱이 없어도 문자나 카카오 알림톡으로 먼저 시험할 수 있습니다
- `applications`, `sessions` 테이블에 필요한 정보가 이미 다 있습니다

## 2. 중간 단계 — PWA

앱스토어에 올리기 전에 **"홈 화면에 추가"** 만으로 앱처럼 쓰게 만들 수 있습니다.

| | 웹 | **PWA** | 네이티브 앱 |
|---|---|---|---|
| 아이콘 생김 | ✕ | ○ | ○ |
| 전체 화면 | ✕ | ○ | ○ |
| 푸시 알림 | ✕ | 안드로이드 ○ / 아이폰 △ | ○ |
| 스토어 심사 | 없음 | 없음 | 있음 |
| 추가 작업 | — | **1~2일** | 2~4주 |

**PWA를 먼저 하세요.** 파일 두 개(`manifest.json`, 서비스워커) 추가하면 끝이고, 앱을 만들지 말지 판단할 시간을 벌어줍니다.

---

## 3. 앱으로 넘어갈 시점

숫자로 판단합니다. 감으로 정하면 너무 이르거나 너무 늦습니다.

- [ ] **센터 10곳 이상**이 매달 일정을 올리고 있다
- [ ] **월 활성 봉사자 300명 이상**
- [ ] "알림이 없어서 까먹었다"는 말이 반복해서 나온다
- [ ] 재방문율이 안정적이다 (한 번 쓴 사람이 다시 온다)

**셋 이상 해당되면** 앱을 만듭니다. 하나도 해당 안 되면 웹을 더 고칠 때입니다.

> 앱이 없어서 안 쓰는 게 아니라, **쓸 이유가 약해서 안 쓰는 경우가 훨씬 많습니다.** 앱은 이유를 만들어주지 않습니다.

---

## 4. 앱을 만들 때의 선택지

| 방식 | 설명 | 웹 재사용 |
|---|---|---|
| **웹뷰 감싸기** | 지금 웹을 앱 껍데기에 넣음 | 거의 100% |
| **React Native / Expo** | 화면을 다시 만들되 로직·DB는 그대로 | 50~70% |
| 완전 새로 | 처음부터 | 0% |

**웹뷰로 시작하는 걸 권합니다.** 푸시 알림과 홈 화면 아이콘만 있으면 충분한데, 그건 웹뷰로도 됩니다. 화면이 느리다는 불만이 실제로 나오면 그때 React Native를 검토하세요.

---

## 5. 체크리스트

지금 웹을 만들면서 지킬 것들입니다.

- [ ] URL을 위 표대로 정하고, **한 번 정하면 안 바꾼다**
- [ ] 센터 코드는 숫자가 아니라 글자 (`happy-dog`)
- [ ] 카카오 개발자 콘솔에 웹·앱 리다이렉트 주소 **둘 다** 등록
- [ ] 아이콘은 파일 안에, 외부 요청 최소화
- [ ] 알림 문구와 시점을 문서로 정해둠 (보내지 않더라도)
- [ ] `manifest.json` 추가해서 PWA로 만들기
- [ ] 공유 링크 미리보기(카카오톡에 뜨는 이미지·제목) 설정
